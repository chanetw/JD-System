🟢 Flow 2: อนุมัติงาน

ผู้อนุมัติ (Approver) ตรวจสอบรายละเอียดงานและอนุมัติหรือปฏิเสธตามเงื่อนไข

📊 Swimlane Diagram

sequenceDiagram actor A as Approver participant UI as UI System participant DB as Database participant Notify as Notification A->>UI: เข้าหน้า "Approvals Pending" UI->>DB: ดึงรายการงาน pending_approval DB-->>UI: แสดงตาราง approvals waiting A->>UI: คลิกงาน เพื่อดูรายละเอียด UI-->>A: แสดง Job Details + Brief A->>A: ตรวจสอบ brief, ไฟล์, SLA Note over A: ตัดสินใจ... alt Approve A->>UI: กดปุ่ม "อนุมัติ" + เพิ่ม comment UI->>DB: update status = "approved" UI->>Notify: ส่งแจ้งเตือน Approver/Admin else Reject A->>UI: กดปุ่ม "ปฏิเสธ" + reason UI->>DB: update status = "rejected" UI->>Notify: ส่งแจ้งไป Requester end DB-->>UI: บันทึก Approval Record UI-->>A: แสดงข้อความสำเร็จ

📋 รายละเอียด Flow

1

เข้าถึง Approvals Dashboard

  • Approver เข้าสู่ระบบด้วย credentials
  • ระบบ redirect ไปยังแดชบอร์ด โดยแสดง:
    • Jobs pending approval (รอการอนุมัติของตัวเอง)
    • Activity feed จากงานที่อนุมัติแล้ว
    • SLA warnings (งานใกล้หมดเวลา)
2

เลือกงานที่ต้องอนุมัติ

  • ดูตารางรายการงาน pending (sort by create_date, SLA status)
  • Approver เลือกงาน หรือ click "View Details"
  • ระบบแสดง Job Detail Page พร้อม:
    • Job Title, Type, Brief text
    • Attachment files (input files, brief documents)
    • Created by, Created at, Due Date (SLA)
    • Approval flow template (step ต่อไป)
3

ตรวจสอบและวิเคราะห์

  • Approver อ่านรายละเอียด brief + requirements
  • ดาวน์โหลดและตรวจสอบไฟล์ input
  • ตรวจสอบ deadline & SLA status:
    • 🟢 Green: Still plenty of time
    • 🟡 Yellow: Due within 2 days
    • 🔴 Red: Urgent/Overdue
  • อ่าน comments (ถ้ามีจาก Requester หรือ approvers ชั้นก่อนหน้า)
4

ตัดสินใจอนุมัติ

  • ถ้ากำลังจะอนุมัติ:
    • ระบบแสดง "Approval" button พร้อมเพิ่ม comment
    • Approver ใส่ comment (ถ้าต้องการ) เช่น "Approved - clear requirements"
    • Click "Approve"
  • ถ้ากำลังจะปฏิเสธ:
    • Click "Reject" button
    • ใส่เหตุผล (required) เช่น "Need more specific target audience"
    • Click "Confirm Rejection"
5

ระบบประมวลผล Approval

  • ถ้า Approve:
    • สร้าง Approval Record (approver, timestamp, comment)
    • Update Job status → "approved"
    • ส่งแจ้งเตือนไปยัง Approver/Admin ตัวต่อไป (ถ้ามีหลายชั้น)
  • ถ้า Reject:
    • Update Job status → "rejected"
    • บันทึก Approval Record (rejection_reason)
    • ส่งแจ้งไป Requester พร้อมเหตุผล + instructions to resubmit
  • สร้าง Activity Log entry

✅ Success Criteria

  • ✓ Approval record สร้างขึ้นมา (พร้อม approver, timestamp, comment)
  • ✓ Job status เปลี่ยนไปเป็น "approved" หรือ "rejected" ตามการตัดสินใจ
  • ✓ Notification ส่งไปยังผู้เกี่ยวข้อง (Approver ชั้นถัดไป หรือ Requester)
  • ✓ Activity Log บันทึก approval action

⚠️ Multi-Level Approval

  • ถ้า job_type มี approval flow หลายชั้น (เช่น Manager → Director)
  • Approver ชั้นแรก approve → job ไปรอ Approver ชั้นที่สอง
  • ทำซ้ำขั้นตอนนี้ ไปจนกว่าจะ approve จนเสร็จสิ้น
  • ถ้า reject ที่ชั้นไหน → งานกลับไปแจ้ง Requester ทั้งสิ้น
