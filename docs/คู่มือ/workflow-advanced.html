🔴🟡 Flow 7-12: Exception & Advanced Flows

🔴 Flow 7: ขอปฏิเสธงาน (Assignee Request Rejection)

Status Progression: assigned/in_progress → assignee_rejected

Actors: Assignee → ระบบ → Approver

sequenceDiagram actor E as Assignee participant UI as UI System participant DB as Database E->>UI: ดู Job Detail (status: assigned/in_progress) E->>E: ตัดสินใจขอปฏิเสธ E->>UI: กดปุ่ม "Request Rejection" UI-->>E: แสดง form: reason, justification E->>UI: เขียนเหตุผล (เช่น "Scope changed" / "Need rebrief") E->>UI: กดปุ่ม "Submit" UI->>DB: update status = "assignee_rejected" UI->>DB: บันทึก rejection_request note over UI: ส่งแจ้ง Approver เพื่อตัดสินใจ UI-->>E: "Request submitted - awaiting approval"
  • ใคร: Assignee ขอปฏิเสธเพราะหลายเหตุผล
  • ผลลัพธ์: Job รอการตัดสินใจ Approver (Flow 8 หรือ 9)

🔴 Flow 8: อนุมัติการปฏิเสธ (Approver Approves Rejection)

Status Progression: assignee_rejected → rejected_by_assignee

Actors: Approver (ตัดสินใจ) → ระบบ

sequenceDiagram actor A as Approver participant UI as UI System participant DB as Database A->>UI: ดูรายการ "Rejection Requests" A->>UI: เลือก request ที่ต้องการ UI-->>A: แสดง Job + Assignee's reason A->>A: ตัดสินใจอนุมัติ A->>UI: กดปุ่ม "Approve Rejection" UI->>DB: update status = "rejected_by_assignee" note over UI: Job ปิด/บันทึกเสร็จแล้ว UI->>UI: ส่งแจ้ง Requester
  • ผลลัพธ์: Job ถูกปฏิเสธไปจริง (ปิดงาน)
  • Requester: จะได้แจ้งเตือนพร้อมเหตุผล

🔴 Flow 9: ไม่อนุมัติการปฏิเสธ (Deny Rejection)

Status Progression: assignee_rejected → assigned (กลับไปทำต่อ)

sequenceDiagram actor A as Approver participant UI as UI System A->>UI: ดู Rejection Request A->>A: ตัดสินใจว่า Assignee ต้องทำต่อ A->>UI: กดปุ่ม "Deny Request" + comment UI-->>A: A ใส่เหตุผลว่าทำไมต้องทำต่อ A->>UI: ยืนยัน note over UI: Status กลับไป "assigned" UI->>UI: ส่งแจ้ง Assignee: "Continue your work"
  • ผลลัพธ์: Assignee กลับไปทำงานต่อ
  • SLA: ยังคงนับต่อ (ไม่ reset)

🟡 Flow 10: ขยายเวลา SLA (Extend SLA)

Status Progression: assigned/in_progress → (SLA extended)

sequenceDiagram actor E as Assignee participant UI as UI System participant DB as Database E->>UI: ดู Job + SLA countdown note over E: Deadline ใกล้มาก! ต้องขอขยาย E->>UI: กดปุ่ม "Request Extension" UI-->>E: แสดง form: days to extend, reason E->>UI: ใส่ "3 days" + reason E->>UI: ยืนยัน UI->>DB: update due_date = due_date + 3 days UI->>DB: create extension record UI->>UI: ส่งแจ้ง Approver/Requester UI-->>E: "Extension granted"
  • ใคร: Assignee ขอขยายเมื่อ SLA ใกล้หมดเวลา
  • ผลลัพธ์: due_date เลื่อนออกไป N วัน

🟡 Flow 11: Job Chaining - Parent/Child (Automatic)

Status Progression: parent: completed → child: submitted → pending_approval

sequenceDiagram participant Parent as Parent Job participant System as DJ System participant Child as Child Job Parent->>System: Status = "completed" System->>System: ค้นหา child jobs alt Child Job Exists System->>Child: Create child job (auto-generated) Child-->>Child: status = "submitted" → "pending_approval" System->>System: ส่งแจ้ง Approizers else No Child System->>System: End workflow end
  • ใคร: ระบบ (automatic) เมื่อ parent job complete
  • เงื่อนไข: Parent job มี linked child jobs
  • ผลลัพธ์: Child job อัตโนมัติสร้างและส่งรอการอนุมัติ

🟡 Flow 12: Magic Link Actions (Email Direct Actions)

Status Progression: No status change (direct action via email)

sequenceDiagram actor Approver participant Email as Email Client participant System as DJ System System->>Email: ส่ง Job Notification Email Email-->>Email: แสดง buttons: [Approve] [Reject] [View Details] Approver->>Email: คลิก [Approve] button ใน email Email->>System: POST /api/magic-link/approve?token=JWT System->>System: verify JWT token System->>System: execute approval action System-->>Email: แสดง confirmation page
  • ใคร: Approver, Assignee (via email)
  • สิทธิ: approve, reject, view (ไม่ต้อง login)
  • ความปลอดภัย: JWT token + expiration

✅ ขออนุมัติการสร้างเสร็จสิ้น
