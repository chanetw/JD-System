🟢 Flow 1: สร้างและส่งงาน

ผู้สั่งงาน (Requester) สร้างงาน Design ใหม่และส่งเข้าสู่ระบบพร้อมรายละเอียดและไฟล์ brief

📊 Swimlane Diagram

sequenceDiagram actor R as Requester participant UI as UI System participant DB as Database participant Notify as Notification R->>UI: เปิดหน้า "สร้างงานใหม่" UI-->>R: แสดงฟอร์มกรอกรายละเอียด R->>R: กรอกข้อมูล (ชื่อ, ประเภท, brief, ไฟล์) R->>UI: กดปุ่ม "ส่งงาน" UI->>DB: บันทึก Job (status: submitted) DB-->>UI: ยืนยันสร้างสำเร็จ UI->>DB: สร้าง Activity Log UI->>Notify: ส่งแจ้งเตือน Approver UI-->>R: แสดงข้อความ "ส่งงานสำเร็จ" Notify-->>Notify: Job ready for approval (pending_approval)

📋 รายละเอียด Flow

1

เข้าถึงหน้าสร้างงาน

  • Requester เข้าสู่ระบบด้วย credentials ของตนเอง
  • คลิกปุ่ม "สร้างงานใหม่" หรือ "New Job Request"
  • ระบบแสดงฟอร์มสร้างงาน 4 ขั้นตอน (Steps)
2

กรอกข้อมูลพื้นฐาน

  • ชื่องาน (Job Title): "Redesign Landing Page" เป็นต้น
  • ประเภทงาน (Job Type): เลือกจาก dropdown (Graphic Design, Web Design, ฯลฯ)
  • Project: เลือก Project ที่เกี่ยวข้อง
  • BUD: Business Unit Division (บ่อยครั้งสอบ validate auto ตามทีมของผู้สั่ง)
  • Description: รายละเอียดเพิ่มเติม
3

ใส่ Brief & Specifications

  • Brief Text: คำอธิบายรายละเอียดความต้องการ
  • External Brief Link: URL ไปยังเอกสาร brief ภายนอก (เช่น Google Docs)
  • Target Audience: กลุ่มเป้าหมาย (ถ้ามี)
  • Reference Files: อ้างอิง design ที่มีอยู่ (ถ้ามี)
4

อัปโหลด Attachment

  • Input Files: ไฟล์ brief, สเปค, ภาพอ้างอิง
  • ระบบอนุญาต: PDF, Word, JPG, PNG, Figma link, เป็นต้น
  • Drag & Drop: สามารถลากไฟล์มาวางหรือเลือกจากคอมพิวเตอร์
  • ขีดจำกัด: 10MB ต่อไฟล์, นับรวมได้ถึง 50MB
5

ยืนยันและส่งงาน

  • Requester กดปุ่ม "ส่งงาน" (Submit Job)
  • ระบบ validate form ทั้งหมด:
    • ✓ ชื่องาน (required)
    • ✓ ประเภทงาน (required)
    • ✓ Brief หรือ Link brief อย่างน้อยหนึ่งอย่าง (required)
  • ถ้าผ่าน validation ทั้งหมด → บันทึกลงฐานข้อมูล
6

ระบบประมวลผล

  • สร้าง Job Record: status = "submitted" → "pending_approval"
  • กำหนด SLA: ระบบคำนวณ due_date ตาม job_type SLA + working_days
  • สร้าง Activity Log: บันทึก "Created by Requester" + timestamp
  • ส่งแจ้งเตือน: Email/Notification ไปยัง Approvers ตามเส้นทางอนุมัติของ job_type นั้น

✅ Success Criteria

  • ✓ Job สร้างขึ้นมาเรียบร้อย (ปรากฏในระบบ)
  • ✓ Status = "pending_approval" (พร้อมรอการอนุมัติ)
  • ✓ Approvers ได้รับแจ้งเตือน
  • ✓ Requester เห็นข้อความยืนยันสำเร็จ
  • ✓ Activity Log บันทึก timestamp + creator

⚠️ Edge Cases & Notes

  • Multi-Approver: ถ้า job_type มีเส้นทางอนุมัติหลายระดับ จะส่งแจ้งเตือนไปยัง Approver ชั้นแรกก่อน
  • Assignee Auto-Assignment: ถ้า job_type มีการกำหนด default assignee โหลดได้โดย admin ก่อน
  • Parent Job Support: Requester สามารถเลือก parent job หากงานนี้ใหญ่และต้องแยกส่วน
  • File Validation: ระบบ scan ไฟล์ เพื่อป้องกัน malware (ถ้าใช้ antivirus integration)
